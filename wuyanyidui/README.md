# 财务舞弊111 · 舞弊审计调查 AI 助理

> **定位**：舞弊审计调查岗位的 AI 助理。**负责"提示与整理"，岗位人员负责"判断与决定"。**
> 不做舞弊认定、不做风险定级、不建议处置；所有输出均可回溯、可复核、可推翻。

一个**可运行、可交互、可扩展**的 Web 应用 + 本地 API 服务，覆盖舞弊调查的七个工作维度。

---

## 一、快速开始（三种方式）

### 方式 1：完整模式（推荐）——双击 `start.bat`

```
双击 start.bat
```

- 自动启动本地服务并打开浏览器（默认 http://127.0.0.1:5178/web/index.html）
- 启用：**大模型智能分析**、**MySQL 数据库接入**、**网页工商信息采集**
- 需要 Node.js 18+（[下载](https://nodejs.org/)）。未安装时脚本会给出提示并说明如何仅用离线模式

### 方式 2：离线模式——直接双击 `web/index.html`

- **无需任何安装、无需联网**，全部离线能力可用：
  预置数据、风险信号筛查、线索梳理、关联方核查、全科目汇总、评分评估、报告生成与导出、方法论知识库问答
- 大模型相关功能自动降级为「本地模式」（基于内置规则与知识库生成，界面明确标注）
- 说明：浏览器禁止 `file://` 页面读取本地 JSON（CORS），因此知识库以**内嵌副本** `web/assets/js/core/kb-embedded.js` 提供；修改 `data/knowledge/fraud-kb.json` 后请运行 `node tools/build-embedded-kb.js` 重新生成

### 方式 3：命令行

```bash
node server/server.js          # 启动本地服务
# 或指定端口
FRAUD111_PORT=8080 node server/server.js   # Windows: set FRAUD111_PORT=8080 && node server/server.js
```

### 第一次使用建议路径

1. 顶部导航 → **工作台** → 点「**加载预置演示数据**」
2. 点「**▶ 一键完成全流程分析**」（约 1 秒跑完五个模块）
3. 依次浏览：**风险信号识别** → **线索台账** → **关联方核查** → **评分评估** → **报告草稿**
4. 到 **测试示例** 页点「运行全部样例」，查看 10 个内置验收用例的判定结果
5. 换成自己的数据：**数据汇总** 页上传 Excel/CSV 或连接 MySQL

## 二、功能与岗位需求对照

| 维度 | 功能 | 页面 | 助理做什么 | **人工必须做什么** |
|---|---|---|---|---|
| F1 | 风险信号识别与预警 | 风险信号识别 | 统计异常（3σ/IQR/MAD）+ 规则异常（R01–R09）双路筛查、排序、打标签 | 判断是否构成异常、异常的原因 |
| F2 | 可疑交易线索梳理 | 线索台账 | 按「对手方+事项+时间窗」归集、资金链路追踪、四流交叉核对、优先级排序并给理由 | 线索取舍、核查顺序、调查方向 |
| F3 | 关联方穿透与关联交易核查 | 关联方核查 | 关键人员关联、股权穿透、频次规模异常、资金合同错配四类初筛 | 关联关系是否成立、是否构成利益输送 |
| F4 | 数据自动汇总与采集 | 数据汇总 | 支持 Excel/CSV/MySQL/预置四类接入；全科目逐级汇总；借贷平衡与数据质量报告 | 口径是否符合审计方案、数据是否可用 |
| F5 | 舞弊可能性参考评估 | 评分评估 | 七类舞弊 × 四维指标加权评分，输出**参考区间** | 风险等级的最终定级 |
| F6 | 舞弊调查分析报告起草 | 报告草稿 | 十节结构报告初稿 + 图表 + 证据缺口 + 核查建议 + 强制声明，可导出 HTML/MD/CSV | 结论、定稿、签发、上报 |
| F7 | 偏好记忆与口径校验 | 设置（全局） | 记忆常用口径/阈值/白名单/报告模板，每次分析前回显并提示变更 | 阈值与口径的最终确认 |

### 九条识别规则

| 规则 | 名称 | 默认口径（可在设置中调整并记忆） |
|---|---|---|
| R01 | 大额 | 单笔 ≥ 500,000 元 |
| R02 | 整数 | 10 万整数倍且 ≥ 100,000 元 |
| R03 | 拆分 | 同一对手方 7 日内累计 ≥ 200,000 元且单笔均 < 50,000 元 |
| R04 | 期末突击 | 会计期间最后 5 个自然日且 ≥ 200,000 元 |
| R05 | 个人卡 | 对手方为自然人且用途非工资/报销 |
| R06 | 高频 | 同一对手方单月笔数 > 剔除峰值后的历史月均 × 3 |
| R07 | 双向对冲 | 15 日内与同一对手方收付金额差异 ≤ 10% |
| R08 | 非工作时间 | 22:00–06:00 或非工作日 |
| R09 | 无业务支撑 | 流水有金额但无对应凭证且未勾对银企对账 |

### 统计离群三种口径（并行输出，由人判断采用哪一种）

- **3σ**：`|x − μ| > 3σ`（对极端值敏感，要求样本量较大）
- **IQR**：`x > Q3 + 1.5 × IQR`（不依赖正态假设，箱线图标准口径）
- **MAD**：`0.6745 × |x − 中位数| / MAD > 3.5`（最稳健）

样本量 < 8 或金额无波动时，自动降级并在界面说明原因。

## 四、API 接口

服务默认监听 `127.0.0.1:5178`（仅本机，不暴露局域网）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 服务与大模型配置状态（Key 脱敏返回） |
| POST | `/api/llm` | 转发大模型请求，支持 SSE 流式。Key 由服务端注入 |
| GET | `/api/db/status` | MySQL 客户端与连接配置检测 |
| GET | `/api/db/tables?tables=...` | 读取 10 张业务表（受白名单约束） |
| POST | `/api/fetch-page` | 采集公开工商信息（域名白名单约束） |

```bash
curl http://127.0.0.1:5178/api/health

curl -X POST http://127.0.0.1:5178/api/llm \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"说明你能辅助舞弊审计做什么"}],"stream":false}'
```

### 配置 `.env`

```ini
FRAUD111_LLM_KEY=sk-xxxx          # 大模型 Key（只在服务端使用，前端永不可见）
FRAUD111_LLM_BASE=https://api.deepseek.com
FRAUD111_LLM_MODEL=deepseek-flash
FRAUD111_PORT=5178

# 可选：MySQL（需本机已安装 mysql 命令行客户端并加入 PATH）
FRAUD111_DB_HOST=127.0.0.1
FRAUD111_DB_USER=root
FRAUD111_DB_PASSWORD=
FRAUD111_DB_NAME=fraud111
```

## 六、安全与合规设计

| 措施 | 实现方式 |
|---|---|
| API Key 不落前端 | Key 只存于服务端 `.env`/环境变量，前端经 `/api/llm` 转发；`/api/health` 仅返回脱敏值 |
| 只监听本机 | `127.0.0.1` 绑定，不暴露局域网 |
| 数据不出本机 | 上传文件在浏览器内解析，不上传服务器 |
| 减少敏感外发 | 发给大模型的仅为问题与结构化摘要（笔数/金额/规则编号），不含完整流水与身份证号 |
| 越界表述防护 | 输出后置检查 + 自动改写；报告强制声明不可删除 |
| 不编造制度条款 | 知识库明确不含企业制度与法规条文；涉及合规判断一律提示"需人工对照现行制度确认" |
| 网页采集白名单 | 仅允许公开工商信息站点；失败降级为"请人工上传" |

### 强制声明（报告与关键输出固定附带）

> 本报告由 AI 助理基于现有数据自动生成，为辅助分析材料，不替代调查结论。报告中的风险等级、可能性评估、线索优先级均为参考值，须由调查人员复核确认。本报告不构成对任何单位或个人的舞弊认定。

### 表述规范

| ❌ 禁止 | ✅ 应当 |
|---|---|
| 该笔交易构成舞弊 | 该笔交易触发 X 项风险信号，建议人工核查 |
| 该供应商是关联方 | 该供应商关联关系命中 X 项特征，建议人工确认工商信息 |
| 风险等级为高 | 综合参考风险分值 X 分，处于待核实区间，需人工复核后定级 |
| 建议立案调查 | 由岗位人员评估是否启动正式调查 |
| 证据链已闭合 | 存在 N 项证据缺口，需补充取证 |

## 七、内置演示数据说明

预置数据（`演示数据（合成）`）为**完全虚构**的合成数据：1 家投资控股公司 2025 全年数据，含
562 笔银行流水、1,152 张凭证、2,778 条分录、52 个会计科目、20 名员工、11 家客户、12 家供应商。

数据中**刻意植入**了七类舞弊的可识别信号，用于验证系统能力：

| 植入模式 | 用于验证 |
|---|---|
| 同一自然人 4 个季度末各收 100 万元，23:41 记账、无凭证 | R01/R02/R04/R05/R08/R09 叠加 → 参考高风险 |
| 同一供应商 7 日内 5 笔 48,000 元 | R03 拆分 |
| 与某客户短期收付金额近似（差异 < 4%） | R07 双向对冲 → 资金链路「疑似回流」 |
| 客户法人 = 员工、收款账号 = 员工工资卡 | 关键人员关联「账号重合」「法人同名」 |
| 供应商法人与员工姓名编辑距离 = 1 | 姓名相似（并提示需用身份证号复核防同名误判） |
| 付款收款账号与档案登记不一致 | 资金合同错配 |
| 1 张借贷不平凭证、4 笔未勾对流水 | F4 借贷平衡校验与数据质量报告 |

> 所有企业名称、个人姓名、证件号、银行账号均为虚构，仅用于功能演示。

## 八、已知边界

1. **资金链路只覆盖本方可见流水**：对手方之后的多层流转需外部协查，"疑似回流"仅为特征提示。
2. **股权穿透依赖工商信息**：内置示例 5 条；真实使用需上传或采集工商档案（未接入商业工商数据库）。
3. **MySQL 接入需本机 mysql 客户端**：未安装时请改用 Excel/CSV 上传。
4. **`.xlsx` 解析需联网加载 SheetJS**：离线时请转存为 CSV。
5. **评分卡权重带主观性**：分值与参考区间用于分配注意力，不等于舞弊概率。
6. **不替代任何调查程序**：不含访谈、函证、现场核查，无法据此确认业务真实性。
