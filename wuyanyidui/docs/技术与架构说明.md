# 财务舞弊111 · 技术与架构说明

## 一、设计目标与约束

| 目标 | 落地决策 |
|---|---|
| 双击即用、无需安装 | 前端为原生 HTML/CSS/JS，**零 NPM 依赖**；`web/index.html` 可 `file://` 直接运行 |
| 离线可用 | 分析引擎全在前端；知识库为本地 JSON；图表为手写 SVG/CSS，不依赖图表库 CDN |
| API Key 不泄露 | 所有模型调用经服务端 `/api/llm` 转发，Key 只在服务端 `.env` |
| 结论可复核 | 每个判定都输出中间量（σ、IQR 上界、MAD 上界、命中依据、计分公式） |
| 不越界 | 输出后置合规检查 + 强制声明 + 结论留空 |
| 可测试 | 分析引擎为**纯函数**（无 DOM 依赖），可在 Node 中直接单测 |

## 二、分层架构

```
┌──────────────────────── 浏览器（PC） ────────────────────────┐
│  web/index.html                                              │
│    ├─ pages/      9 个页面（渲染 + 交互）                     │
│    ├─ app.js      应用外壳：AppState / 路由 / 跨模块联动       │
│    ├─ ui.js       组件库：表格、SVG 图表、弹窗、状态占位        │
│    ├─ analysis/   六个分析引擎（纯函数，可单测）               │
│    │              risk-alert / clue-sort / linkage            │
│    │              aggregation / scorecard / report            │
│    └─ core/       config / util / stats / memory / rag        │
│                   demo-data / datasource / llm                │
└──────────────────────────────────────────────────────────────┘
                 │ 仅「AI 生成」「数据库」「网页采集」走网络
                 ▼
┌──────────────── 本地代理 server/server.js（127.0.0.1） ───────┐
│  GET  /api/health       服务与大模型状态（Key 脱敏）           │
│  POST /api/llm          转发大模型（SSE 流透传），注入 Key      │
│  GET  /api/db/status    MySQL 客户端检测                      │
│  GET  /api/db/tables    读取 10 张表（表名白名单）             │
│  POST /api/fetch-page   采集公开工商信息（域名白名单）          │
│  静态服务：项目根目录（使 index.html 与 data/ 都可访问）        │
└──────────────────────────────────────────────────────────────┘
                 │
                 ▼
        DeepSeek / MySQL（本机 mysql CLI）
```

**关键决策**：静态根目录设为**项目根**（而非 `web/`），使 `web/index.html` 与 `data/knowledge/` 同源可达；知识库路径按 `../data/...` 与 `data/...` 两种候选探测，`file://` 与 `http://` 均可加载。

## 四、六个分析引擎

### F1 `risk-alert.js` — 双路筛查

```
输入：银行流水 + 凭证 + 员工档案 + 阈值/白名单/期间
  ├─ 统计离群：baseline(均值/σ/Q1/Q3/IQR/MAD) → evalValue → {3σ, IQR, MAD}
  ├─ 规则异常：R01–R09 逐笔判定，每条输出 {code, detail, evidence}
  ├─ 舞弊映射：RULE_TO_FRAUD（规则 → 七类舞弊）
  └─ 参考等级：统计命中 + 规则种类数 + 结构性规则加权（软规则封顶，避免刷屏）
输出：信号清单（含全部中间量）+ 规则统计 + 舞弊分布 + 拆分分组 + 校验提示
```

- R06 基线用"剔除峰值后的历史月均"，避免单月异常拉高基线导致漏报
- R09 区分强命中（无凭证且未勾对）与弱支撑（仅缺合同/发票号，不单独计分）
- 样本量 < 8 或 σ = 0 时降级并在 `baseline.reason` 说明

### F2 `clue-sort.js` — 线索归集

```
聚合键 = 对手方 | 事项（用途关键词归一）
每条线索：
  ├─ fund_chain_tracing      本方账户→对手方→凭证；断点 / 疑似回流（收付比 ≥ 70%）
  ├─ fund_business_crosscheck 流水金额 vs 线索内凭证分录金额（含税 20% 容差）
  ├─ four_flow_check         合同/发票/资金/货物 四流逐项缺口
  └─ priority = 金额40 + 规则种类30 + 关联方20 + 链路完整性10（逐项输出理由）
```

**实现要点**：业务金额只取**线索内流水所对应凭证**的分录，而非该对手方全部分录，避免把无关交易混入造成误报。

### F3 `linkage.js` — 四类关联核查

| 核查 | 判定逻辑 |
|---|---|
| 关键人员关联 | 身份证同号 / **银行账号重合**（对手账号 = 员工工资卡）/ 法人同名 / 姓名相似（编辑距离 ≤ 1，仅限中文姓名） |
| 股权穿透 | 股东链层级、本单位员工作为股东、交叉持股/代持特征、工商异常标记 |
| 频次规模异常 | 单对手方占比 > 40%、单月峰值 / 剔除峰值的月均 > 3、非在册对手方 |
| 资金合同错配 | 流水对手方 ≠ 凭证往来单位（按 `voucher_no` 精确关联）、收款账号 ≠ 档案登记账号、有合同/凭证但无发票 |

**实现要点**：
- 法人 = 联系人时去重，避免同一人重复计分
- 不做"日期+金额"猜测式匹配（会误报），仅在 `voucher_no` 明确时关联凭证
- 姓名相似明确标注"须以身份证号复核，避免同名误判"

### F4 `aggregation.js` — 全科目汇总

```
末级科目取总账发生额/余额
  → 逐级向上汇总（父级 = Σ子级，按父级方向调整符号）
  → 借贷平衡：全量 / 逐期间 / 逐凭证
  → 数据质量：空值率、重复、借贷不平、未勾对、跨期、外键缺失、科目表缺失
  → 口径说明卡（期间、科目数、层级、币种、汇总公式、余额规则）
```

### F5 `scorecard.js` — 七类 × 四维评分

```
七类舞弊 × 4 维，每维 0–5 分（由原始指标线性映射，公式随输出展示）
  → 加权（权重合计 100，可人工调整并自动归一化）
  →总分 0–100 → 参考区间（0–29 / 30–59 / 60–79 / 80–100）
```

- 每个区间文案**内置**"（需人工复核后定级）"，由配置统一保证，不依赖调用方
- 每维输出 `rawText`（原始指标）+ `rule`（计分公式），支持"为什么是这个分"
- 各维度上界按真实审计经验标定（如个人卡占比 15%、期末占比 25%），避免全部顶格 5 分失去区分度

### F6 `report.js` — 十节报告

```
汇总 F1–F5 → 组装 10 节数据模型 → 渲染独立 HTML（内联 CSS，可打印）/ Markdown
强制声明来自 config.MANDATORY_DISCLAIMER，结论段固定留空
缺失模块时标记 missingModules 并在报告内警示，仍附强制声明
```

## 五、跨模块联动与状态

`AppState` 为单一数据源，`PIPELINE` 声明依赖顺序：

```js
riskAlert → clueSort → linkage → aggregation → scorecard → report
```

任一模块 `set()` 后，`markStale()` 把下游全部标记过期；左侧导航显示 `!`，目标页显示提示条。更换数据源则清空全部下游结果。

`runPipeline()` 串行执行，并在关联方核查完成后**重算一次线索**，使线索的"关联方命中标志"反映最新核查结果。

## 六、大模型集成

### 流式与推理模型的坑

`deepseek-flash` 是**推理模型**：先流式输出 `reasoning_content`（思考过程），再输出 `content`（正文）。

- 若把 `max_tokens` 设得过小（如 1600），预算会被思考过程耗尽，`content` 始终为空 → 界面出现"长时间无响应"
- 处理方式：
  1. `max_tokens` 默认提升到 3000
  2. `reasoning_content` 与 `content` **分开回调**，思考过程显示为"正在思考（N 字）"，不混入正文
  3. 若结束时正文为空，自动降级为本地模式并说明原因

### 降级策略

```
有代理 + 有 Key  → 真模型（SSE 流式）
有代理 + 无 Key  → 本地模式（401 后降级）
无代理          → 本地模式（连接失败后降级）
```

本地模式不是"假装模型"：界面明确标注 **「⚠ 本地模式」** 并给出原因，内容由内置规则与知识库生成。

### 越界表述防护

模型输出统一经过 `assertSafeText`：

```js
FORBIDDEN_PATTERNS = [/构成舞弊/, /存在舞弊行为/, /建议立案/, /建议处理[某该]\S{0,6}/, ...]
```

命中则 `sanitizeText` 改写为合规表述（如"建议由岗位人员评估是否启动正式调查"），并在界面提示改写了多少处。

## 七、组件库实现要点

全部为**手写**，无第三方图表库：

| 组件 | 实现 |
|---|---|
| 散点图 | 内联 SVG，X=日期（线性映射）、Y=金额，点半径按等级 |
| 箱线图 | SVG：箱体 Q1–Q3、中位线、须线、IQR 上界虚线、离群点 |
| 柱状图 | CSS `flex` + 百分比宽度（轻量、可自适应） |
| 雷达图 | SVG `polygon`，7 轴 × 4 级网格 |
| 关系网络 | SVG 环形布局（本公司居中，员工/主体分环） |
| 表格 | 排序 / 多条件筛选 / 搜索 / 分页 / 行内展开 / 按列导出 CSV |

**健壮性**：所有图表对 `NaN`/缺失值做兜底 —— 早期版本因坐标写出 `NaN` 导致 SVG 属性解析报错，现已在 `X()`/`Y()` 映射与箱线图输入处统一防护，并在浏览器测试中断言"运行期间无未捕获异常"。

## 八、测试策略

### `tests/selftest.js`（183 项，纯 Node）

用 `vm`-free 的 CommonJS 直接 `require` 前端引擎（它们用 UMD 风格挂到 `globalThis`），并注入最小 `localStorage` 垫片。

覆盖：统计口径数学正确性（对照手算值）→ 九规则命中 → 四类关联 → 父级汇总等式 → 评分区间文案 → 报告十节与声明 → 记忆签名 → 知识库 10 个检索用例 → 越界表述检出与改写 → CSV 解析与字段映射 → 结果可复现与性能。

### `tests/browser-smoke.js`（40 项，真实浏览器）

通过 **Chrome DevTools Protocol**（`Target.createTarget` + flattened session）驱动本机 Edge：

1. 加载页面、导航项、API 设置按钮
2. 触发一键流水线，断言五个模块产出
3. 逐页渲染 + 分工提示条存在
4. 表格/图表/口径标注存在，区间文案合规
5. 报告生成与十节结构、强制声明、结论留空
6. 内置测试示例 10/10
7. **真实调用大模型**并检查输出合规
8. 断言全程 0 个未捕获异常

## 九、开发中修复的典型缺陷

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 知识库不加载 | 浏览器中文档数 0，方法论问答全空 | 页面在 `/web/` 下，`data/...` 相对路径 404；原代码用 `status` 判断吞掉了失败 | 改为多候选路径 + 以响应内容判断，并加异步兜底与顶部状态提示 |
| SSE 无正文 | 流式"成功"但内容为空 | 推理模型把 token 预算用在 `reasoning_content` | 拆分两个回调、提高预算、空正文降级 |
| 图表 NaN | 控制台 `Expected length "NaN"` | 箱线图输入缺少 min/max 时坐标写出 NaN | 输入兜底 + 映射函数防 NaN |
| 字段映射冲突 | "收付标志"被识别成"是否个人"，方向丢失 | `FIELD_ALIAS` 中"收付标志"未列在 direction，反而命中 counterparty_is_person 的"是否个人"子串逻辑 | 补齐 direction 同义词 |
| 重复计数 | 同一法人=联系人时命中两次 | 未去重 | 按姓名去重 |
| 误报错配 | 无凭证流水被误判"合同主体不一致" | 用"日期+金额"猜测凭证 | 仅按 `voucher_no` 精确关联 |
| 交叉核对虚高 | 业务金额把该对手方全部分录都算进来 | 取数范围过大 | 限定为线索内流水对应的凭证分录 |
| R08 刷屏 | 非工作时间占信号 55% | 演示数据把正常交易也放在周末 | 正常业务只落工作日，仅保留植入信号 |
| 评分顶格 | 七类中多数维度满分 5 | 计分上界过松 | 按审计经验重新标定各维上界 |

## 十、扩展指引

**加一条识别规则**：
1. `core/config.js` 增加阈值项
2. `analysis/risk-alert.js` 的 `RULES` 加定义、逐笔判定处加命中逻辑、`RULE_TO_FRAUD` 加映射
3. 在 `pages/risk.js` 的筛选项与 `tests/selftest.js` 的规则清单中登记

**加一个评分维度**：改 `config.SCORE_CARD`（加 `key/label/weight`），在 `scorecard.js` 的 `DIMS` 里给该 key 提供 `{score, rawText, rule, weight}`。

**换模型**：只需改 `.env` 的 `FRAUD111_LLM_BASE` / `FRAUD111_LLM_MODEL`（服务端为 OpenAI 兼容协议）。若目标模型不支持推理字段，`reasoning_content` 为空的场景天然兼容。
